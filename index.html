Featured: SEC-EDGAR-GPT

A 124M-parameter GPT-2 trained from scratch on 1.55B tokens of SEC EDGAR filings (10-K, 10-Q, and corporate disclosures) — about 8 hours on a single RTX 4070, converging to a validation loss of 2.28. The model generates convincing boilerplate: risk factors, MD&A sections, business descriptions. The whole pipeline — training, paper, chatbot, and website — was built in three days with an AI coding agent, and shared inside a global bank where it received 200+ views.

  • Code — github.com/lzwjava/sec-edgar-gpt
  • Paper — sec-edgar-gpt.pdf
  • Model — huggingface.co/lzwjava/sec-edgar-gpt-124m-hf

It also seeded a research direction: treating financial tokens differently from natural-language tokens to improve generation accuracy — inspired by a friend's work on recurrent transformers.

The nanoGPT fork

Forked karpathy/nanoGPT and extended it across 45 commits (Nov 2025 – Apr 2026):

  • Dataset pipelines: FineWeb-Edu (10B+ tokens, shard-based), OpenWebText 10k (fast iteration), Wikipedia local (plain-text dump, no HF download)
  • Six training configs scaled by VRAM: 124M for RTX 4070, 760M for MI300X, 1.5B for H200, plus smoke tests
  • Inline tensor-shape annotations through CausalSelfAttention, MLP, and GPT — exact shapes at every step, e.g. x: (B, T, C) e.g. (1, 5, 1600)

GitHub: lzwjava/nanoGPT

Training rules learned the hard way

  • Verify code, environment, and data before spending GPU hours — a broken pipeline always fails in training.
  • Check platform timeouts and balance; make every run resumable so intermediate results survive interruptions.
  • Scale in orders of magnitude: millions of tokens, then billions, then trillions.
  • Dirty data will always surface downstream. Fix root causes, not symptoms.

02 / Inference & serving

Serving open models — from source, with honest numbers

nano-vLLM on an RTX 4070

Ran nano-vLLM serving Qwen3-0.6B with flash-attention on the home RTX 4070: 506 tok/s prefill, decode ~4–30 tok/s, and ~1,434 tok/s on a laptop benchmark. Treated as data points, not proof of anything — but they made the serving stack concrete.

SGLang compiled from source

Built SGLang from source — pip install -e "python", resolved a torch/torchaudio CUDA mismatch to 2.11.0+cu130, compiled its three PyO3 Rust extensions — and served Qwen2.5-0.5B through an OpenAI-compatible API on localhost:30010. Also got nano-vLLM running with prebuilt flash-attn==2.8.3 wheels.

llama.cpp on the home cluster

Serving DeepSeek-R1-Distill-Qwen-14B (Q5_K_M GGUF) through llama.cpp on the M40/P100 fleet — with the hard-won settings (--n-gpu-layers 49, batch size, thread counts) that make a 2015-era GPU usable in 2026.

MoE & the serving stack — where the depth is

Studied Mixture-of-Experts end-to-end — DeepSeek-MoE (fine-grained + shared experts), MegaBlocks (dropless block-sparse dispatch), Tutel (all-to-all expert parallelism), Mixtral (8×7B, top-2) — tracing the forward pass: router → MoELayer → FusedMoe (top-k → block-aligned dispatch → 2 fused GEMMs → sum-reduce) → Triton grouped-GEMM.

Concepts being internalized (honestly, some still shallow):

  • Paged KV cache — 256-token blocks, free lists, content-hash prefix caching, copy-on-write sharing
  • Scheduler — chunked prefill for long prompts, decode stepping, preemption under KV pressure
  • CUDA graphs — capturing decode batches to cut kernel-launch overhead
  • Tensor parallelism — all_reduce for row-parallel layers, gather for the LM head

The honest loop: read 20% → modify 30% → break things 30% → submit 20%. A few weeks in; enough to follow a MoE conversation, not yet enough to improve a serving system.

The breakthrough that made it work

After trial and error across Huananzhi B75, ASUS A68HM-E, and MSI B150M boards, the magic on the MSI Z170A Gaming M5 was:

  • Advanced → Windows OS Configuration → Windows 10 WHQL Support = Disabled
  • Above 4G Decoding = Enabled (required for the M40's 64-bit BAR)
  • CSM = Disabled (pure UEFI for correct PCIe resource allocation)
  • M40 in PCI_E1, the top x16 CPU-attached slot

Result: nvidia-smi showed the full 11,520 MiB (ECC reserves 512), a burn test hit 100% utilization / 6.12 TFLOPS FP32 (~90% of peak) at 35–39°C.

Impact: for ~1000–1200 CNY you get 12 GB of CUDA VRAM — enough for 7B–14B models at Q4–Q8, 27B at aggressive quants (IQ1_M ~6.3 GB), batch inference, and LoRA fine-tuning. That's ~100 CNY per GB. The M40 needs a llama.cpp build with -DCMAKE_CUDA_ARCHITECTURES=52; the P100 needs =60.

GPU teardowns — learning hardware from broken cards

Bought broken Quadro 401 / 2000 / 4000 cards on the second-hand market, dismantled them, and studied the boards: VRM circuitry (MOSFETs, inductors, capacitors), memory chip layout, and how each generation's architecture (Fermi → …) differs. Every PCB is a blueprint of engineering decisions.

02 / 推理与部署

部署开源模型——从源码编译，数字如实

RTX 4070 上的 nano-vLLM

在家用 RTX 4070 上用 nano-vLLM 以 flash-attention 部署 Qwen3-0.6B：prefill 506 tok/s，decode 约 4–30 tok/s，笔记本基准约 1,434 tok/s。只当作数据点，不当作任何论断——但足以让推理栈变得具体。

从源码编译 SGLang

从源码构建 SGLang——pip install -e "python"，把 torch/torchaudio 的 CUDA 版本冲突修复到 2.11.0+cu130，编译其三个 PyO3 Rust 扩展——并在 localhost:30010 通过 OpenAI 兼容 API 部署 Qwen2.5-0.5B。同时也用预编译的 flash-attn==2.8.3 wheel 跑通了 nano-vLLM。

家庭集群上的 llama.cpp

在 M40/P100 集群上用 llama.cpp 部署 DeepSeek-R1-Distill-Qwen-14B（Q5_K_M GGUF）——依靠来之不易的参数（--n-gpu-layers 49、批大小、线程数），让 2015 年的显卡在 2026 年依然能打。

MoE 与推理栈——水最深的地方

端到端研读混合专家（Mixture-of-Experts）——DeepSeek-MoE（细粒度 + 共享专家）、MegaBlocks（无丢弃的块稀疏派发）、Tutel（全对全专家并行）、Mixtral（8×7B，top-2）——并追踪前向传播：router → MoELayer → FusedMoe（top-k → 块对齐派发 → 二次融合 GEMM → 求和归约）→ Triton grouped-GEMM。

正在内化的概念（老实说，有些还很浅）：

  • 分页 KV 缓存——256-token 块、空闲链表、内容哈希前缀缓存、写时复制共享
  • 调度器——长提示的分块 prefill、decode 步进、KV 满时的抢占
  • CUDA graphs——捕获 decode 批次以降低 kernel 启动开销
  • 张量并行——行并行层做 all_reduce、LM head 做 gather

诚实的循环：读 20% → 改 30% → 弄坏 30% → 提交 20%。才几周时间；能跟上 MoE 的讨论，但还不足以自己改进一个推理系统。

让一切都跑起来的关键突破

在 Huananzhi B75、ASUS A68HM-E、MSI B150M 上来回试错之后，MSI Z170A Gaming M5 上的关键配置是：

  • Advanced → Windows OS Configuration → Windows 10 WHQL Support = Disabled
  • 开启 Above 4G Decoding（M40 需要 64 位 BAR）
  • 关闭 CSM（纯 UEFI 模式，PCIe 资源分配才正确）
  • 把 M40 插在 PCI_E1（直连 CPU 的顶部 x16 插槽）

结果：nvidia-smi 显示完整 11,520 MiB（ECC 预留 512 MiB），烧机测试达到 100% 利用率 / FP32 6.12 TFLOPS（约峰值的 90%），温度稳定在 35–39°C。

意义：大约 1000–1200 元就能给家庭实验室增加 12 GB CUDA 显存——足以运行 Q4–Q8 量化的 7B–14B 模型、激进量化（IQ1_M 约 6.3 GB）的 27B 模型、批处理推理与 LoRA 微调。约 100 元每 GB。M40 需要以 -DCMAKE_CUDA_ARCHITECTURES=52 编译 llama.cpp；P100 需要 =60。
